# 🍳 Git Cooking Workshop

Bienvenue dans **Git Cooking Workshop**, un atelier pratique pour apprendre Git et GitHub en contribuant à un livre de recettes collaboratif.

## 🎯 Objectifs pédagogiques

À la fin de cet atelier, vous saurez :

- Cloner un dépôt Git.
- Créer et utiliser une branche.
- Modifier des fichiers Markdown.
- Inspecter vos modifications avec `git status` et `git diff`.
- Créer des commits clairs et pertinents.
- Publier une branche sur GitHub avec `git push`.
- Ouvrir et documenter une Pull Request (PR).
- Relire les contributions d'autres participants.
- Comprendre le merge, la synchronisation et le rebase.

## 🍽️ Le scénario

Bienvenue dans notre livre de recettes collaboratif !

Ce livre contient volontairement des erreurs : fautes de frappe, ingrédients manquants, quantités incohérentes, étapes mal formulées ou problèmes de mise en forme Markdown.

Votre mission est de contribuer à son amélioration en identifiant et en corrigeant ces erreurs.

Comme dans un véritable projet collaboratif, chaque modification doit être proposée via une Pull Request et relue par un autre participant.

## 🚀 Comment participer ?

1. Explorez les recettes disponibles dans le dossier [`recipes/`](recipes/).
2. Choisissez une recette à améliorer.
3. Consultez les consignes de contribution dans [`CONTRIBUTING.md`](CONTRIBUTING.md).
4. Créez votre propre branche pour travailler sur votre correction.
5. Modifiez la recette et vérifiez vos changements.
6. Créez un commit décrivant clairement votre correction.
7. Publiez votre branche sur GitHub et ouvrez une Pull Request vers le dépôt original.
8. Faites relire votre contribution par un autre participant.
9. Prenez en compte les commentaires éventuels avant le merge final.

## 📏 Règles de contribution

- Une Pull Request doit corriger un problème précis.
- Limitez vos modifications aux fichiers nécessaires.
- Ne modifiez pas directement la branche `main`.
- Utilisez des noms de branches explicites.
- Rédigez des messages de commit clairs.
- Expliquez le problème corrigé et les changements effectués dans votre Pull Request.
- Relisez les contributions des autres participants de manière constructive.
- Respectez les retours des reviewers et corrigez votre contribution si nécessaire.

## 🤝 La review fait partie de l'exercice

Chaque participant doit également relire la Pull Request d'un autre participant.

Lors d'une review, vérifiez notamment :

- Le problème signalé est-il réellement corrigé ?
- Les changements sont-ils pertinents et limités au besoin ?
- La recette reste-t-elle cohérente et facile à comprendre ?
- Le Markdown est-il correctement formaté ?
- La description de la Pull Request correspond-elle aux modifications ?

L'objectif n'est pas simplement de valider une PR, mais d'apprendre à examiner et à discuter des modifications proposées.

## 🌱 Apprendre en contribuant

Il ne s'agit pas seulement de corriger des recettes : l'objectif est de comprendre comment les développeurs collaborent sur un projet avec Git et GitHub.

Vous allez découvrir le cycle complet d'une contribution :

**Fork → Clone → Branch → Modify → Commit → Push → Pull Request → Review → Merge**

Les exercices évolueront progressivement, depuis les manipulations dans l'interface GitHub jusqu'à l'utilisation de Git en ligne de commande, à la synchronisation des branches et à la résolution de conflits.
